# EFitMi — working notes

Read `README.md` first for what this is. These are the things that are easy
to get wrong and expensive to rediscover.

## The one rule

Every number this app shows must trace back to the card the user actually
outlined. Anything that lets an assumed value reach a result — a default
body size, a guessed height, a fabricated fallback width — is the bug this
project exists to avoid, no matter how plausible the output looks. The
reference project failed exactly here, and its README claimed otherwise.

Consequences to preserve:

- The card box seeded from shoulder span is a *starting position only*. If
  the user never moves it, `adjusted` is false and both the calibrate and
  results screens say so. Don't quietly drop that.
- `refineWidth` uses the contour reading only when it corroborates the
  landmarks. Don't restore `max(landmark, contour)`.
- `getBodyWidthAtHeight` returns `null` when it finds no edge. Don't give it
  a fallback value — a failed scan has measured nothing.

## Architecture

Fully client-side. `src/lib/measure.ts` is the pipeline; the flow is
`page.tsx` → Intro → Capture → Calibrate → Results.

`service/` is a Flask port of the same geometry, **not** wired into the app.
It exists as the route back to MiDaS depth refinement. If you change the
geometry in one, change it in the other, and re-check parity.

`public/mediapipe/` is gitignored and generated by `postinstall`. The WASM
runtime and pose model are served from our own origin on purpose — a CDN
being unreachable would break pose detection entirely.

## Calibration data

Shoulder and chest are calibrated against a tailor's sheet for one subject
(body shoulder 18in, tight chest 37in) via the MediaPipe world-landmark
path, which owes nothing to the card scale. Both reproduce the sheet.

Tailor sheets write "tight / with ease" — the body figure and the figure a
garment is cut to. `EASE_CM` holds the allowances from that sheet; a
measurement missing from it gets no garment figure rather than an invented
one.

**Do not calibrate waist against a trouser-waist measurement.** A trouser
waist is taken over clothing at the waistband, low on the hips; the app
measures the natural waist. They are different points and the numbers are
not comparable. This has already come up once.

## Things that bit us

- **MediaPipe `Holistic()` defaults to `static_image_mode=False`**, which is
  video-tracking mode: a shared detector carries state between calls and
  returns different landmarks for the same photo. Any server-side pose work
  must pass `static_image_mode=True`.
- **mediapipe 1.x removed `mp.solutions`.** `service/` is pinned to 0.10.20
  and needs numpy 1.x. Don't bump without porting to the tasks API.
- **The calibrate box lives in photo pixels, not screen pixels.** Screen
  coordinates change with zoom and pan; the measurement divides by the photo
  pixel width. `src/lib/viewport.ts` does the conversion and its round trip
  is tested — keep it lossless.
- **Pointer events bubble.** The card box's `pointerdown` must
  `stopPropagation`, or the root's pan handler overwrites the drag. This
  shipped broken once.
- **`react-hooks/set-state-in-effect` is an error here.** Derive state at
  render (`userValue ?? computedDefault`) instead of syncing it in an effect.

## Verifying changes

```bash
npm test && npx tsc --noEmit && npx eslint . && npm run build
```

When you add a test for a bug, reintroduce the bug and confirm the test
fails. One test here looked right and caught nothing — the linear-scaling
test didn't detect a return to `max()`, because with fixed landmarks both
terms are fixed and `max()` of them still scales linearly.

The camera flow can't be verified from a sandbox without a real camera.
Chromium's `--use-file-for-fake-video-capture=<file.y4m>` with a photo of a
person will drive the whole flow, including pose detection.

## Scope

Phase 1 is capture → calibrate → measure, nothing else. Fabric capture,
garment generation, try-on, accounts, persistence, a native app, and
automatic card detection are explicitly out. Flag it rather than building it.
